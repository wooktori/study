## 1. 렉시컬 스코프 외 다른 스코프 방식 비교

스코프(Scope)란 **변수에 접근할 수 있는 유효 범위**이다.

### 렉시컬 스코프 (Lexical Scope)

함수가 **선언된 위치**를 기준으로 스코프가 결정된다. 자바스크립트가 사용하는 방식이다.

```js
const x = "전역";

function outer() {
  const x = "outer";

  function inner() {
    console.log(x); // "outer" — 선언된 위치 기준
  }

  inner();
}

outer();
```

### 동적 스코프 (Dynamic Scope)

함수가 **호출된 위치**를 기준으로 스코프가 결정된다. Bash, 초기 Lisp 등이 사용한다.

### 비교

| 구분        | 렉시컬 스코프                 | 동적 스코프            |
| ----------- | ----------------------------- | ---------------------- |
| 기준        | 함수가 **선언된** 위치        | 함수가 **호출된** 위치 |
| 결정 시점   | 코드 작성 시 (컴파일 타임)    | 실행 시 (런타임)       |
| 예측 가능성 | ✅ 높음                       | ⚠️ 낮음                |
| 사용 언어   | JS, Python, C, Java 등 대부분 | Bash, 초기 Lisp        |

> 렉시컬 스코프가 예측하기 쉬워 대부분의 현대 언어에서 채택한다.

## 2. 자바스크립트 스코프 규칙의 특징

### 다른 언어와 비교

```js
// 자바스크립트 — var는 함수 스코프
function foo() {
  if (true) {
    var x = 1; // 블록 { } 무시, 함수 전체에서 유효
  }
  console.log(x); // 1 (다른 언어였다면 에러)
}
```

```java
// Java — 블록 스코프
void foo() {
  if (true) {
    int x = 1;
  }
  System.out.println(x); // 컴파일 에러 — x는 if 블록 안에서만 유효
}
```

### 자바스크립트의 특징

| 특징                         | 설명                                                     |
| ---------------------------- | -------------------------------------------------------- |
| `var`는 함수 스코프          | 블록 `{ }`을 무시, 함수 단위로만 스코프 생성             |
| `let`, `const`는 블록 스코프 | ES6 이후 다른 언어와 동일하게 동작                       |
| 호이스팅                     | 선언이 스코프 최상단으로 끌어올려짐                      |
| 전역 객체와 연결             | `var`로 선언한 전역 변수는 `window.변수명`으로 접근 가능 |
| 클로저 활용 빈도 높음        | 1급 함수 + 렉시컬 스코프로 클로저가 자연스럽게 만들어짐  |

```js
// var — 전역 선언 시 window에 붙음
var globalVar = "나는 전역";
console.log(window.globalVar); // "나는 전역"

// let — window에 붙지 않음
let globalLet = "나는 블록";
console.log(window.globalLet); // undefined
```

## 3. var, let, const 사용 기준

### 차이 정리

| 구분           | `var`                   | `let`               | `const`             |
| -------------- | ----------------------- | ------------------- | ------------------- |
| 스코프         | 함수 스코프             | 블록 스코프         | 블록 스코프         |
| 재선언         | ✅ 가능                 | ❌ 불가             | ❌ 불가             |
| 재할당         | ✅ 가능                 | ✅ 가능             | ❌ 불가             |
| 호이스팅       | ✅ (undefined로 초기화) | ✅ (TDZ, 접근 불가) | ✅ (TDZ, 접근 불가) |
| 전역 객체 연결 | ✅                      | ❌                  | ❌                  |

### 언제 무엇을 쓸까?

```js
// const — 기본값으로 사용. 재할당이 필요 없는 경우
const API_URL = "https://api.example.com";
const user = { name: "철수" }; // 객체 자체를 재할당하지 않으면 const
user.name = "영희"; // 내부 값 변경은 가능

// let — 반드시 재할당이 필요한 경우만
let count = 0;
count++; // 재할당 필요

for (let i = 0; i < 3; i++) {} // 루프 카운터

// var — 현대 JS에서는 사용하지 않는다
// 함수 스코프, 호이스팅 등으로 예측하기 어려운 버그 유발
```

> **원칙:** 기본적으로 `const` → 재할당 필요 시 `let` → `var`는 사용하지 않는다.

## 4. 호이스팅이 발생하는 이유

### 호이스팅이란?

자바스크립트 엔진이 코드를 실행하기 전, **선언을 먼저 처리**하는 동작이다.

```js
console.log(x); // undefined (에러가 아님)
var x = 1;
console.log(x); // 1
```

엔진이 내부적으로 아래처럼 처리한다.

```js
var x; // 선언만 끌어올림
console.log(x); // undefined
x = 1; // 할당은 그 자리에
console.log(x); // 1
```

### 발생하는 이유

자바스크립트 엔진은 코드를 두 단계로 처리한다.

```
1단계 (파싱) : 전체 코드를 훑으며 변수/함수 선언을 수집 → 메모리에 등록
2단계 (실행) : 코드를 위에서 아래로 실행
```

1단계에서 선언을 미리 등록하기 때문에, 선언 전에 접근해도 에러가 나지 않는다.

### var vs let/const 호이스팅 차이

```js
// var — undefined로 초기화됨
console.log(a); // undefined
var a = 1;

// let/const — TDZ (Temporal Dead Zone) 발생
console.log(b); // ReferenceError: Cannot access 'b' before initialization
let b = 1;
```

`let`과 `const`도 호이스팅은 되지만, **초기화 전까지 접근할 수 없는 TDZ 구간**이 존재한다.

```
선언 ----[TDZ]---- 초기화 ----> 사용 가능
let b;             b = 1;       console.log(b)
```

### 함수 호이스팅

```js
// 함수 선언식 — 전체가 호이스팅됨
greet(); // "안녕" ✅
function greet() {
  console.log("안녕");
}

// 함수 표현식 — 변수만 호이스팅, 함수는 X
greet2(); // TypeError: greet2 is not a function
var greet2 = function () {
  console.log("안녕");
};
```

## 5. 엄격 모드와 비엄격 모드

### 엄격 모드란?

`"use strict"`를 선언해 **느슨한 JS 문법을 더 엄격하게 제한**하는 모드이다.

```js
"use strict"; // 파일 또는 함수 최상단에 선언

// 또는 ES6 모듈(import/export)은 자동으로 엄격 모드
```

### 비엄격 모드에서 허용되는 위험한 코드들

```js
// 1. 선언 없이 변수 사용 — 전역 변수 생성
x = 1; // 비엄격: 전역 변수 생성 / 엄격: ReferenceError

// 2. 중복 파라미터
function foo(a, a) {} // 비엄격: 허용 / 엄격: SyntaxError

// 3. this가 전역 객체
function bar() {
  console.log(this); // 비엄격: window / 엄격: undefined
}

// 4. 읽기 전용 속성에 쓰기
const obj = {};
Object.defineProperty(obj, "x", { value: 1, writable: false });
obj.x = 2; // 비엄격: 조용히 무시 / 엄격: TypeError
```

### 구분하는 이유

| 이유           | 설명                                           |
| -------------- | ---------------------------------------------- |
| 버그 조기 발견 | 잘못된 코드가 조용히 넘어가지 않고 에러를 던짐 |
| 보안 강화      | `this`가 전역 객체를 가리키지 않아 실수 방지   |
| 최적화 용이    | 엔진이 예측 가능한 코드를 더 잘 최적화함       |
| 미래 대비      | 향후 추가될 예약어 사용 제한                   |

> ES6 모듈(`import`/`export`)과 클래스는 자동으로 엄격 모드가 적용된다.

## 6. 클로저는 자바스크립트만의 개념인가?

아니다. **1급 함수(First-class function)와 렉시컬 스코프를 지원하는 언어라면 클로저를 사용할 수 있다.**

### 다른 언어의 클로저

```python
# Python
def outer():
    message = "안녕"
    def inner():
        print(message)  # outer의 변수를 기억
    return inner

fn = outer()
fn()  # "안녕"
```

```swift
// Swift
func outer() -> () -> Void {
    let message = "안녕"
    return {
        print(message)  // 클로저가 message 캡처
    }
}

let fn = outer()
fn()  // "안녕"
```

```go
// Go
func outer() func() {
    message := "안녕"
    return func() {
        fmt.Println(message)
    }
}

fn := outer()
fn()  // "안녕"
```

### 클로저를 지원하지 않는 언어

초기 C, 초기 Java처럼 함수를 1급 객체로 취급하지 않거나 렉시컬 스코프가 없으면 클로저를 사용할 수 없다.

> 자바스크립트에서 특히 클로저가 자주 언급되는 이유는, 콜백/비동기/모듈 패턴 등에서 **클로저 활용 빈도가 매우 높기 때문**이다.

## 7. 클로저와 메모리 누수

### 메모리 누수가 발생하는 상황

클로저가 외부 변수를 참조하는 한, 그 변수는 GC(가비지 컬렉터)의 대상이 되지 않는다.

```js
function createButtons() {
  const largeData = new Array(1000000).fill("데이터"); // 대용량 데이터

  document.getElementById("btn").addEventListener("click", function () {
    console.log(largeData.length); // largeData를 참조
  });
  // 버튼이 DOM에 있는 한 largeData는 메모리에서 해제되지 않음
}
```

### 해결 방법

```js
// 1. 필요한 값만 추출해서 사용
function createButtons() {
  const largeData = new Array(1000000).fill("데이터");
  const length = largeData.length; // 필요한 값만 추출

  document.getElementById("btn").addEventListener("click", function () {
    console.log(length); // largeData 전체가 아닌 length만 참조
  });
  // largeData는 이제 GC 대상이 됨 ✅
}

// 2. 이벤트 리스너 제거
function setup() {
  const data = "데이터";

  function handleClick() {
    console.log(data);
  }

  document.getElementById("btn").addEventListener("click", handleClick);

  // 필요 없어지면 제거
  return function cleanup() {
    document.getElementById("btn").removeEventListener("click", handleClick);
  };
}

const cleanup = setup();
cleanup(); // 메모리 해제

// 3. WeakMap/WeakRef 사용
const cache = new WeakMap(); // 키 객체가 GC되면 자동으로 캐시도 해제
```

### 클로저 성능 주의사항

```js
// ❌ 루프 안에서 클로저 생성 — 함수 객체가 매번 생성됨
for (let i = 0; i < 1000; i++) {
  arr[i] = () => i * 2; // 1000개의 함수 객체 생성
}

// ✅ 함수를 밖으로 빼서 재사용
const double = (i) => i * 2;
for (let i = 0; i < 1000; i++) {
  arr[i] = double; // 같은 함수 참조
}
```

## 8. 커링이란?

**여러 인수를 받는 함수를 인수 하나씩 받는 함수들의 체인으로 변환하는 기법**이다.

```js
// 일반 함수
function add(a, b) {
  return a + b;
}
add(1, 2); // 3

// 커링된 함수
function curriedAdd(a) {
  return function (b) {
    return a + b;
  };
}
curriedAdd(1)(2); // 3
```

### 커링의 장점

**1. 부분 적용 (Partial Application) — 함수 재사용**

```js
const multiply = (a) => (b) => a * b;

const double = multiply(2); // a=2로 고정
const triple = multiply(3); // a=3으로 고정

double(5); // 10
triple(5); // 15

// 실무 예시 — 세율 계산
const applyTax = (rate) => (price) => price * (1 + rate);

const applyVAT = applyTax(0.1); // 부가세 10%
const applyLuxury = applyTax(0.3); // 사치세 30%

applyVAT(1000); // 1100
applyLuxury(1000); // 1300
```

**2. 함수 합성과 궁합이 좋다**

```js
const pipe =
  (...fns) =>
  (x) =>
    fns.reduce((v, f) => f(v), x);

const process = pipe(
  applyTax(0.1), // 세금 적용
  (price) => price + 500, // 배송비 추가
);

process(1000); // (1000 * 1.1) + 500 = 1600
```

**3. 지연 실행 — 설정과 실행을 분리**

```js
// 로그 함수 — 레벨을 먼저 설정, 메시지는 나중에
const log = (level) => (message) => console.log(`[${level}] ${message}`);

const info = log("INFO");
const error = log("ERROR");

info("서버 시작"); // [INFO] 서버 시작
error("DB 연결 실패"); // [ERROR] DB 연결 실패
```

### 커링 vs 일반 함수

| 구분      | 일반 함수          | 커링             |
| --------- | ------------------ | ---------------- |
| 호출 방식 | `f(a, b)`          | `f(a)(b)`        |
| 부분 적용 | ❌ 불편            | ✅ 자연스러움    |
| 함수 합성 | ⚠️ 가능하나 복잡   | ✅ 깔끔하게 연결 |
| 가독성    | 인수가 적으면 유리 | 체인이 길면 유리 |

## 9. 비동기 코드에서 클로저 주의점

### 주의점 1 — 루프 + var + 비동기

```js
// ❌ var는 하나의 i를 공유
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// 결과: 3, 3, 3

// ✅ let은 반복마다 새로운 i
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// 결과: 0, 1, 2
```

### 주의점 2 — 오래된 값 참조 (Stale Closure)

클로저가 오래된 값을 캡처해 최신 값을 반영하지 못하는 상황이다.

```js
// React useState 예시
function Counter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setCount(count + 1); // ❌ count가 0으로 고정됨 (클로저가 초기값 캡처)
    }, 1000);
    return () => clearInterval(id);
  }, []); // 빈 의존성 배열 — count 변화를 감지 못함
}

// ✅ 해결 — 함수형 업데이트 사용
useEffect(() => {
  const id = setInterval(() => {
    setCount((prev) => prev + 1); // 항상 최신 값 기반
  }, 1000);
  return () => clearInterval(id);
}, []);
```

### 주의점 3 — 비동기 완료 시점의 값

```js
let user = { name: "철수" };

async function fetchAndLog() {
  const snapshot = user; // 현재 값을 캡처

  await fetch("/api/data");

  // await 후에 user가 바뀌었을 수 있음
  console.log(user.name); // 최신 값 (바뀔 수 있음)
  console.log(snapshot.name); // 캡처 시점 값
}

user = { name: "영희" }; // 비동기 중에 변경
fetchAndLog();
```

### 주의점 4 — Promise 체인에서의 클로저

```js
// ❌ 의도치 않은 참조
function processItems(items) {
  let result = [];

  items.forEach((item) => {
    fetch(`/api/${item.id}`)
      .then((res) => res.json())
      .then((data) => {
        result.push(data); // result를 클로저로 참조
      });
  });

  return result; // ❌ 비동기 완료 전에 빈 배열 반환
}

// ✅ Promise.all 사용
async function processItems(items) {
  const results = await Promise.all(
    items.map((item) => fetch(`/api/${item.id}`).then((res) => res.json())),
  );
  return results;
}
```

### 핵심 정리

| 상황                      | 주의점                         | 해결법                            |
| ------------------------- | ------------------------------ | --------------------------------- |
| 루프 + 비동기             | `var`는 공유된 i 참조          | `let` 사용                        |
| 오래된 값 (Stale Closure) | 초기 값이 클로저에 고정됨      | 함수형 업데이트, 의존성 배열 관리 |
| 비동기 완료 시점          | 캡처 시점 vs 완료 시점 값 차이 | 필요한 값을 미리 스냅샷           |
| 비동기 완료 전 반환       | 빈 값 반환                     | `async/await` + `Promise.all`     |
