## 1. 실행 환경마다 이벤트를 다루는 방식이 다른 이유

### 이벤트는 환경의 산물

이벤트는 **어떤 일이 일어났음을 알리는 신호**다. 무엇이 일어날 수 있는지는 실행 환경이 결정한다.

```
브라우저: 사용자가 클릭, 스크롤, 키보드 입력 → DOM 이벤트
Node.js : 파일 읽기 완료, 네트워크 요청 수신 → EventEmitter
앱(React Native): 터치, 제스처, 화면 회전 → Native 이벤트
```

### 브라우저 — DOM 이벤트

브라우저는 HTML 요소와 사용자 상호작용을 중심으로 이벤트 시스템이 설계됐다.

```js
// DOM 요소에 리스너 등록
button.addEventListener("click", (e) => {
  console.log(e.target); // 클릭된 요소
});

// 이벤트 객체에 브라우저 전용 정보 포함
document.addEventListener("mousemove", (e) => {
  console.log(e.clientX, e.clientY); // 마우스 좌표
});
```

특징:
- 이벤트가 DOM 트리를 따라 **버블링/캡처링**으로 전파된다
- `addEventListener` / `removeEventListener`로 관리
- `Event`, `MouseEvent`, `KeyboardEvent` 등 이벤트 타입이 세분화됨

### Node.js — EventEmitter

Node.js는 파일 I/O, 네트워크 같은 비동기 작업 완료를 알리는 데 이벤트를 사용한다.

```js
const EventEmitter = require("events");
const emitter = new EventEmitter();

// 리스너 등록
emitter.on("data", (chunk) => {
  console.log("데이터 수신:", chunk);
});

// 이벤트 발생
emitter.emit("data", "Hello");

// 파일 읽기 완료 이벤트
const fs = require("fs");
const stream = fs.createReadStream("file.txt");
stream.on("data", (chunk) => console.log(chunk));
stream.on("end", () => console.log("완료"));
stream.on("error", (err) => console.error(err));
```

특징:
- DOM 트리가 없으므로 버블링/캡처링 없음
- `on` / `off` / `emit`으로 관리
- 이벤트 객체 없이 직접 데이터를 인자로 전달

### 환경별 이벤트 비교

| 구분          | 브라우저 (DOM)              | Node.js (EventEmitter)   |
| ------------- | --------------------------- | ------------------------ |
| 이벤트 주체   | HTML 요소, window, document | 스트림, 서버, 커스텀 객체 |
| 등록 방법     | `addEventListener`          | `.on()`                  |
| 전파          | 버블링 / 캡처링             | 없음                     |
| 이벤트 객체   | `Event` 객체 (좌표, 키 등)  | 직접 전달한 인자         |
| 내장 이벤트   | click, keydown 등 수백 개   | data, end, error 등      |

> **정리:** 이벤트를 다루는 방식이 환경마다 다른 이유는 각 환경이 다루는 대상과 문제가 다르기 때문이다. 브라우저는 DOM 트리 기반의 사용자 인터랙션, Node.js는 I/O 비동기 작업을 중심으로 설계됐다.

## 2. handleEvent 메서드를 가진 객체를 사용하는 이유와 사례

### 콜백 함수 방식의 문제

```js
class Counter {
  constructor() {
    this.count = 0;
    // ❌ this가 버튼 요소를 가리켜 count에 접근 불가
    button.addEventListener("click", function() {
      this.count++; // this = button → undefined
    });
  }
}
```

```js
class Counter {
  constructor() {
    this.count = 0;
    // 화살표 함수로 해결 가능하지만 removeEventListener 불가
    button.addEventListener("click", () => {
      this.count++;
    });
  }
}
```

화살표 함수는 `this` 문제를 해결하지만, 리스너 제거가 불가능하다. 매번 `bind(this)`를 해도 새 함수가 생성돼 제거할 수 없다.

### handleEvent 객체 방식

`addEventListener`의 두 번째 인자로 **`handleEvent` 메서드를 가진 객체**를 넘기면, 이벤트 발생 시 `객체.handleEvent(event)`가 호출된다. 이때 `this`는 해당 객체를 가리킨다.

```js
class Counter {
  constructor(button) {
    this.count = 0;
    this.button = button;
    button.addEventListener("click", this); // 객체 자체를 전달
  }

  handleEvent(e) {
    // this = Counter 인스턴스 (자동으로 바인딩됨)
    this.count++;
    console.log(`클릭 ${this.count}회`);
  }

  destroy() {
    this.button.removeEventListener("click", this); // 동일 객체로 제거 가능
  }
}

const counter = new Counter(button);
// 나중에 제거
counter.destroy();
```

### 사례 1 — 여러 이벤트를 한 객체에서 처리

```js
class Modal {
  constructor(el) {
    this.el = el;
    this.el.addEventListener("click", this);
    document.addEventListener("keydown", this);
  }

  handleEvent(e) {
    // 이벤트 타입에 따라 분기
    if (e.type === "click") this.handleClick(e);
    if (e.type === "keydown") this.handleKeydown(e);
  }

  handleClick(e) {
    if (e.target === this.el) this.close();
  }

  handleKeydown(e) {
    if (e.key === "Escape") this.close();
  }

  close() {
    this.el.style.display = "none";
    this.el.removeEventListener("click", this);
    document.removeEventListener("keydown", this);
  }
}
```

### 사례 2 — 상태를 가진 일회용 핸들러

```js
class OneTimeHandler {
  constructor(button, maxClicks) {
    this.count = 0;
    this.maxClicks = maxClicks;
    this.button = button;
    button.addEventListener("click", this);
  }

  handleEvent() {
    this.count++;
    console.log(`${this.count}/${this.maxClicks}`);
    if (this.count >= this.maxClicks) {
      this.button.removeEventListener("click", this);
      this.button.disabled = true;
    }
  }
}

new OneTimeHandler(button, 3); // 3번 클릭 후 비활성화
```

### 콜백 함수 vs handleEvent 비교

| 구분              | 콜백 함수                  | handleEvent 객체          |
| ----------------- | -------------------------- | ------------------------- |
| this 바인딩       | 수동 처리 필요 (bind/화살표) | 자동으로 객체를 가리킴   |
| 리스너 제거       | bind 시 참조 보관 필요     | 동일 객체로 바로 제거     |
| 여러 이벤트 처리  | 함수별로 분리              | handleEvent에서 한 곳에서 |
| 상태 관리         | 외부 변수 필요             | 객체 내부에 캡슐화        |

> **정리:** handleEvent 객체를 사용하면 this 바인딩 문제 없이 상태를 캡슐화하고, 동일 객체 참조로 리스너를 쉽게 제거할 수 있다. 여러 이벤트를 한 클래스에서 관리할 때 특히 유용하다.

## 3. 이벤트 버블링과 캡처링으로 나뉜 이유와 실무 사용 방식

### 두 방식이 나뉜 이유 — 브라우저 전쟁

1990년대 넷스케이프와 IE가 이벤트 전파 방향을 서로 다르게 구현했다.

```
넷스케이프: 캡처링 (위 → 아래)
  document → html → body → div → button

Internet Explorer: 버블링 (아래 → 위)
  button → div → body → html → document
```

W3C가 표준화할 때 둘 다 채택해서 **캡처링 → 타깃 → 버블링** 순서로 통합했다.

### 이벤트 전파 단계

```html
<div id="outer">
  <div id="inner">
    <button id="btn">클릭</button>
  </div>
</div>
```

```
버튼 클릭 시 전파 순서:

캡처링 단계 (위 → 아래):
  document → html → body → #outer → #inner → #btn

타깃 단계:
  #btn (이벤트 발생 요소)

버블링 단계 (아래 → 위):
  #btn → #inner → #outer → body → html → document
```

```js
// 기본값: 버블링 단계에서 실행
element.addEventListener("click", handler);
element.addEventListener("click", handler, false); // 동일

// 캡처링 단계에서 실행
element.addEventListener("click", handler, true);
element.addEventListener("click", handler, { capture: true }); // 동일
```

### 실무에서 사용하는 방식

**버블링 (기본, 대부분의 경우)**

```js
// ✅ 이벤트 위임 — 부모에서 자식 이벤트 처리
document.querySelector("#list").addEventListener("click", (e) => {
  if (e.target.matches("li")) {
    console.log("항목 클릭:", e.target.textContent);
  }
});
```

**캡처링 (특수한 경우)**

```js
// ✅ 이벤트가 타깃에 도달하기 전에 가로채야 할 때
// 예: 전체 클릭 로깅, 권한 체크
document.addEventListener("click", (e) => {
  if (!isLoggedIn()) {
    e.stopPropagation(); // 하위 리스너 실행 차단
    showLoginModal();
  }
}, true); // 캡처링으로 먼저 실행
```

**전파 중단**

```js
// stopPropagation: 현재 단계 이후 전파 중단
button.addEventListener("click", (e) => {
  e.stopPropagation(); // 부모로 버블링 안 됨
});

// stopImmediatePropagation: 같은 요소의 다른 리스너도 중단
button.addEventListener("click", (e) => {
  e.stopImmediatePropagation();
});
button.addEventListener("click", () => {
  console.log("이건 실행 안 됨");
});
```

### 버블링 vs 캡처링 비교

| 구분        | 버블링                    | 캡처링                     |
| ----------- | ------------------------- | -------------------------- |
| 방향        | 아래 → 위                 | 위 → 아래                  |
| 기본값      | ✅ (세 번째 인자 생략 시)  | `true` 또는 `{capture: true}` 명시 |
| 주요 용도   | 이벤트 위임               | 이벤트 선점/가로채기       |
| 실무 빈도   | 높음                      | 낮음 (특수한 경우)         |

> **정리:** 버블링과 캡처링이 나뉜 이유는 브라우저 전쟁 시대의 구현 차이를 W3C가 통합했기 때문이다. 실무에서는 버블링을 기본으로 사용하고, 이벤트를 타깃 도달 전에 가로채야 할 때만 캡처링을 사용한다.

## 4. 커스텀 이벤트가 필요한 이유와 적용 사례

### 커스텀 이벤트가 필요한 이유

브라우저 내장 이벤트(`click`, `input` 등)는 사용자 인터랙션을 표현하지만, **컴포넌트 간 비즈니스 로직 통신**에는 한계가 있다.

```js
// ❌ 내장 이벤트로는 의도를 표현하기 어려움
element.dispatchEvent(new Event("click")); // "클릭"이지, "로그인 성공"이 아님

// ✅ 커스텀 이벤트로 의도를 명확하게 표현
element.dispatchEvent(new CustomEvent("login:success", {
  detail: { userId: 123, name: "홍길동" }
}));
```

### 사례 1 — 컴포넌트 간 통신 (프레임워크 없이)

```js
// auth.js — 이벤트 발생
async function login(id, pw) {
  const user = await api.login(id, pw);
  document.dispatchEvent(new CustomEvent("auth:login", {
    detail: { user },
    bubbles: true,
  }));
}

// header.js — 이벤트 수신
document.addEventListener("auth:login", (e) => {
  const { user } = e.detail;
  document.querySelector(".username").textContent = user.name;
});

// cart.js — 같은 이벤트 수신
document.addEventListener("auth:login", (e) => {
  loadCart(e.detail.user.id);
});
```

로그인 로직과 UI 업데이트 로직이 분리된다. `auth.js`는 헤더나 카트를 직접 참조하지 않아도 된다.

### 사례 2 — 웹 컴포넌트에서 부모에게 알리기

```js
class DatePicker extends HTMLElement {
  connectedCallback() {
    this.innerHTML = `<input type="date">`;
    this.querySelector("input").addEventListener("change", (e) => {
      // 부모 컴포넌트에게 알림
      this.dispatchEvent(new CustomEvent("date:change", {
        detail: { date: e.target.value },
        bubbles: true,   // 부모로 버블링
        composed: true,  // Shadow DOM 경계 넘어서 전파
      }));
    });
  }
}

customElements.define("date-picker", DatePicker);

// 부모에서 수신
document.querySelector("form").addEventListener("date:change", (e) => {
  console.log("선택된 날짜:", e.detail.date);
});
```

### 사례 3 — 상태 변경 알림

```js
// store.js
class Store {
  #state = { count: 0 };

  increment() {
    this.#state.count++;
    document.dispatchEvent(new CustomEvent("store:update", {
      detail: { ...this.#state }
    }));
  }
}

// counter-display.js
document.addEventListener("store:update", (e) => {
  document.querySelector("#count").textContent = e.detail.count;
});
```

### 사례 4 — 비동기 작업 완료 알림

```js
// uploader.js
async function uploadFile(file) {
  const result = await api.upload(file);
  document.dispatchEvent(new CustomEvent("upload:complete", {
    detail: { url: result.url, filename: file.name }
  }));
}

// preview.js
document.addEventListener("upload:complete", (e) => {
  document.querySelector("img").src = e.detail.url;
});
```

### CustomEvent 옵션

```js
new CustomEvent("이벤트명", {
  detail: { /* 전달할 데이터 */ },
  bubbles: true,   // 버블링 여부 (기본 false)
  cancelable: true, // e.preventDefault() 허용 여부
  composed: true,  // Shadow DOM 경계 넘어 전파 여부
});
```

> **정리:** 커스텀 이벤트는 컴포넌트 간 직접 참조 없이 통신할 때 필요하다. 발생 측은 수신 측을 몰라도 되므로 결합도가 낮아진다. `detail`로 데이터를 전달하고, `bubbles: true`로 DOM 트리를 통한 전파를 설정한다.

## 5. currentTarget과 target을 사용하는 상황

### 차이점

```js
outer.addEventListener("click", (e) => {
  console.log(e.target);        // 실제로 클릭된 요소
  console.log(e.currentTarget); // 리스너가 등록된 요소
});
```

```html
<div id="outer">  <!-- 리스너 등록 -->
  <button id="btn">클릭</button>  <!-- 실제 클릭 -->
</div>
```

```
버튼 클릭 시:
  e.target        = <button#btn>   (클릭된 요소)
  e.currentTarget = <div#outer>    (리스너가 있는 요소)
```

### target을 사용하는 상황 — 이벤트 위임

**어떤 요소가 실제로 이벤트를 발생시켰는지** 알아야 할 때 사용한다.

```js
// ✅ target으로 어떤 항목을 클릭했는지 구분
document.querySelector("#list").addEventListener("click", (e) => {
  // 어떤 li를 클릭했는지 확인
  if (e.target.matches("li")) {
    console.log("선택된 항목:", e.target.dataset.id);
  }

  // 삭제 버튼인지 확인
  if (e.target.matches(".delete-btn")) {
    deleteItem(e.target.closest("li").dataset.id);
  }
});
```

```js
// ✅ 폼 이벤트 — 어떤 input이 변경됐는지 확인
form.addEventListener("change", (e) => {
  console.log("변경된 필드:", e.target.name, e.target.value);
});
```

### currentTarget을 사용하는 상황 — 리스너가 등록된 요소 기준 작업

**리스너가 등록된 요소 자체**를 기준으로 작업할 때 사용한다.

```js
// ✅ 드롭다운 — 외부 클릭 감지
document.addEventListener("click", (e) => {
  // currentTarget = document (리스너 위치)
  // e.target = 실제 클릭 위치
  if (!dropdown.contains(e.target)) {
    dropdown.close();
  }
});
```

```js
// ✅ 폼 제출 — 폼 요소 자체에 접근
form.addEventListener("submit", (e) => {
  e.preventDefault();
  // currentTarget = form (리스너가 등록된 요소)
  const data = new FormData(e.currentTarget);
  api.submit(data);
});
```

```js
// ✅ 애니메이션 — 리스너 등록 요소에 클래스 토글
buttons.forEach(btn => {
  btn.addEventListener("click", (e) => {
    // e.currentTarget = 각 button (리스너가 등록된 요소)
    e.currentTarget.classList.toggle("active");
  });
});
```

### target vs currentTarget 비교

| 구분           | `e.target`                    | `e.currentTarget`             |
| -------------- | ----------------------------- | ----------------------------- |
| 가리키는 요소  | 이벤트가 실제 발생한 요소     | 리스너가 등록된 요소          |
| 버블링 중 변화 | 변하지 않음 (항상 원본)       | 현재 실행 중인 리스너 요소    |
| 주요 용도      | 이벤트 위임, 어떤 요소인지 확인 | 리스너 요소 기준 작업        |
| 화살표 함수 내 | 동일                          | `this`와 동일                 |

> **정리:** `e.target`은 실제 이벤트 발생 요소를 알아야 할 때(이벤트 위임), `e.currentTarget`은 리스너가 등록된 요소 기준으로 작업할 때 사용한다. 이벤트 위임 패턴에서는 대부분 `e.target`으로 어떤 자식 요소인지 판별하고, 부모 요소를 직접 조작할 때 `e.currentTarget`을 쓴다.

## 6. 이벤트 위임의 장점

### 이벤트 위임이란?

개별 자식 요소에 리스너를 등록하는 대신, **공통 부모 요소에 하나의 리스너를 등록**하고 `e.target`으로 이벤트 발생 요소를 구분하는 패턴이다.

```js
// ❌ 직접 등록 — 각 항목마다 리스너
document.querySelectorAll("li").forEach(li => {
  li.addEventListener("click", handleClick);
});

// ✅ 이벤트 위임 — 부모에 하나만 등록
document.querySelector("ul").addEventListener("click", (e) => {
  if (e.target.matches("li")) handleClick(e);
});
```

### 장점 1 — 메모리 절약

```js
// ❌ 항목 1000개 = 리스너 1000개
const items = document.querySelectorAll(".item"); // 1000개
items.forEach(item => item.addEventListener("click", handler));
// 메모리: 리스너 1000개 등록

// ✅ 리스너 1개
document.querySelector(".list").addEventListener("click", (e) => {
  if (e.target.matches(".item")) handler(e);
});
// 메모리: 리스너 1개 등록
```

### 장점 2 — 동적 요소 자동 처리

직접 등록 방식은 나중에 추가된 요소에는 리스너가 없다.

```js
// ❌ 직접 등록 — 나중에 추가된 li는 클릭 안 됨
document.querySelectorAll("li").forEach(li => {
  li.addEventListener("click", handler);
});

const newItem = document.createElement("li");
newItem.textContent = "새 항목";
list.appendChild(newItem);
// newItem에는 리스너 없음 → 클릭해도 반응 없음

// ✅ 이벤트 위임 — 동적으로 추가된 요소도 자동 처리
list.addEventListener("click", (e) => {
  if (e.target.matches("li")) handler(e); // 새 항목도 처리됨
});

list.appendChild(newItem); // 자동으로 클릭 이벤트 작동
```

### 장점 3 — 리스너 관리 단순화

```js
// ❌ 직접 등록 — 제거 시 모든 요소에서 해제 필요
items.forEach(item => item.removeEventListener("click", handler));

// ✅ 이벤트 위임 — 부모 하나만 해제
list.removeEventListener("click", delegatedHandler);
```

### 장점 4 — 실무 패턴 (세분화된 위임)

```js
// 여러 액션을 data 속성으로 구분
document.querySelector("#todo-list").addEventListener("click", (e) => {
  const action = e.target.dataset.action;
  const id = e.target.closest("[data-id]")?.dataset.id;

  if (action === "delete") deleteTodo(id);
  if (action === "complete") completeTodo(id);
  if (action === "edit") editTodo(id);
});
```

```html
<ul id="todo-list">
  <li data-id="1">
    할 일 1
    <button data-action="complete">완료</button>
    <button data-action="edit">수정</button>
    <button data-action="delete">삭제</button>
  </li>
</ul>
```

### 이벤트 위임의 주의사항

```js
// ❌ stopPropagation이 있으면 위임이 작동하지 않음
child.addEventListener("click", (e) => {
  e.stopPropagation(); // 부모로 버블링 차단 → 위임 리스너 실행 안 됨
});

// ❌ focus, blur는 버블링 안 됨 → focusin, focusout 사용
list.addEventListener("focusin", (e) => { // focusin은 버블링됨
  if (e.target.matches("input")) handleFocus(e);
});
```

### 직접 등록 vs 이벤트 위임 비교

| 구분              | 직접 등록                  | 이벤트 위임               |
| ----------------- | -------------------------- | ------------------------- |
| 리스너 수         | 요소 개수만큼              | 1개                       |
| 메모리            | 요소 증가 시 비례 증가     | 일정                      |
| 동적 요소         | 추가 시 재등록 필요        | 자동 처리                 |
| 리스너 제거       | 모든 요소에서 해제 필요    | 부모 하나만 해제          |
| stopPropagation   | 영향 없음                  | 버블링 차단 시 동작 안 함 |

> **정리:** 이벤트 위임은 리스너 수를 줄여 메모리를 절약하고, 동적으로 추가되는 요소도 별도 등록 없이 처리할 수 있다. 리스트, 테이블, 동적 컴포넌트처럼 자식 요소가 많거나 변하는 상황에서 가장 효과적이다.
