## 1. 프로토타입 기반 언어로 설계한 이유와 직접 다뤄야 하는 이유

### 프로토타입 기반으로 설계한 이유

자바스크립트는 1995년 Brendan Eich가 10일 만에 설계했다. 당시 목표는 **간단하고 유연한 웹 스크립팅 언어**였다.

**1. 유연성과 단순성**

클래스 기반 상속은 엄격한 계층 구조를 강제한다. 프로토타입 기반은 객체끼리 직접 연결되므로 더 유연하다.

```js
// 클래스 기반 — 계층 구조가 고정됨
class Animal {}
class Dog extends Animal {}

// 프로토타입 기반 — 객체끼리 직접 연결
const animal = { eat() { console.log("먹는다"); } };
const dog = Object.create(animal); // dog의 프로토타입 = animal
dog.bark = function() { console.log("짖는다"); };

dog.bark(); // "짖는다"
dog.eat();  // "먹는다" — 프로토타입 체인으로 접근
```

**2. Self 언어의 영향**

자바스크립트는 **Self 언어**의 프로토타입 기반 상속을 참고했다. Self는 클래스 없이 객체에서 객체로 직접 상속하는 방식이 더 직관적임을 증명했다.

**3. 런타임 변경 가능**

클래스 기반 언어는 인스턴스 생성 후 클래스 정의를 바꾸기 어렵다. 프로토타입은 런타임에 메서드를 추가하거나 변경할 수 있다.

```js
function Dog(name) {
  this.name = name;
}

const d = new Dog("멍멍이");
d.bark(); // TypeError: d.bark is not a function

// 런타임에 메서드 추가
Dog.prototype.bark = function() {
  console.log(`${this.name}: 왈왈`);
};

d.bark(); // "멍멍이: 왈왈" — 기존 인스턴스에도 즉시 적용
```

### 클래스 문법이 있는데 프로토타입을 직접 다뤄야 하는 이유

ES6 클래스는 **프로토타입 위에 얹은 문법적 설탕(syntactic sugar)** 이다. 내부적으로는 동일하게 프로토타입을 사용한다.

```js
class Dog {
  bark() { console.log("왈왈"); }
}

// 위와 아래는 동일
function Dog() {}
Dog.prototype.bark = function() { console.log("왈왈"); };
```

**1. 런타임 동적 수정**

```js
// 서드파티 라이브러리의 클래스에 메서드 추가 (폴리필 패턴)
Array.prototype.last = function() {
  return this[this.length - 1];
};

[1, 2, 3].last(); // 3
```

**2. 메모리 최적화 확인**

```js
class Person {
  constructor(name) {
    this.name = name;
    this.greet = function() { console.log(this.name); }; // ❌ 인스턴스마다 함수 생성
  }
}

// 프로토타입을 직접 확인해서 최적화
console.log(Person.prototype); // { constructor: f }
// greet가 없음 → 인스턴스마다 함수가 생성되는 낭비 발생 확인 가능
```

**3. 상속 체인 디버깅**

```js
class A {}
class B extends A {}
class C extends B {}

const c = new C();

// 프로토타입 체인 직접 확인
console.log(Object.getPrototypeOf(c));              // B.prototype
console.log(Object.getPrototypeOf(Object.getPrototypeOf(c))); // A.prototype

// instanceof로는 체인 위치를 알 수 없음
console.log(c instanceof A); // true (어디서 왔는지 불명확)
```

**4. Mixin 패턴**

```js
// 클래스는 단일 상속만 지원
// Mixin으로 여러 기능을 조합
const Serializable = {
  serialize() { return JSON.stringify(this); }
};
const Validatable = {
  validate() { return Object.keys(this).length > 0; }
};

class User {}
Object.assign(User.prototype, Serializable, Validatable);

const u = new User();
u.name = "홍길동";
console.log(u.serialize()); // '{"name":"홍길동"}'
console.log(u.validate());  // true
```

### 클래스 vs 프로토타입 직접 조작 비교

| 구분              | 클래스 문법          | 프로토타입 직접 조작     |
| ----------------- | -------------------- | ------------------------ |
| 가독성            | ✅ 높음              | ❌ 낮음                  |
| 런타임 동적 수정  | ❌ 어려움            | ✅ 자유롭게 가능         |
| 다중 상속 (Mixin) | ❌ 단일 상속만       | ✅ 직접 조합 가능        |
| 내부 동작 이해    | ❌ 추상화로 숨겨짐   | ✅ 명시적으로 드러남      |
| 일반적인 사용     | ✅ 권장              | 필요한 경우에만 사용     |

> **정리:** 자바스크립트가 프로토타입 기반인 이유는 유연성과 간결함 때문이다. 클래스 문법이 있어도 프로토타입을 직접 다뤄야 하는 경우는 런타임 동적 수정, Mixin 패턴, 폴리필 작성, 상속 체인 디버깅이다.

## 2. 프로토타입 체인이 동적으로 결정될 때 성능 고려사항

### 프로토타입 체인 조회 비용

프로퍼티를 찾을 때 체인을 따라 올라가면서 탐색한다. 체인이 길수록 탐색 횟수가 늘어난다.

```js
const a = { x: 1 };
const b = Object.create(a); // b.__proto__ = a
const c = Object.create(b); // c.__proto__ = b
const d = Object.create(c); // d.__proto__ = c

// d.x 접근 시 체인 탐색:
// d → c → b → a → 발견 (4번 탐색)
console.log(d.x); // 1
```

### 성능 문제가 발생하는 패턴

**1. 런타임 프로토타입 변경**

```js
class Animal {
  eat() { console.log("먹는다"); }
}

const dog = new Animal();

// ❌ 런타임에 프로토타입 교체 — 엔진 최적화 무력화
Object.setPrototypeOf(dog, {
  eat() { console.log("다르게 먹는다"); }
});
```

V8 같은 JS 엔진은 **히든 클래스(hidden class)** 로 객체 구조를 캐싱한다. 프로토타입을 바꾸면 캐시가 무효화되어 성능이 크게 저하된다.

**2. 깊은 체인에서 반복 접근**

```js
// ❌ 루프 안에서 깊은 체인 반복 접근
for (let i = 0; i < 100000; i++) {
  result += d.x; // 매번 체인 탐색
}

// ✅ 로컬 변수에 캐싱
const x = d.x; // 한 번만 탐색
for (let i = 0; i < 100000; i++) {
  result += x;
}
```

**3. hasOwnProperty 미확인으로 인한 불필요한 탐색**

```js
const obj = { a: 1 };

// ❌ 프로토타입 체인 전체 탐색 후 undefined
console.log("toString" in obj); // true (Object.prototype에 있음)

// ✅ 인스턴스 속성만 확인
console.log(obj.hasOwnProperty("toString")); // false
```

### 엔진 최적화 원리

```
V8 히든 클래스 최적화:
  1. 같은 구조의 객체는 같은 히든 클래스를 공유
  2. 프로퍼티 접근 경로를 캐싱 (인라인 캐시)
  3. 구조가 바뀌면 히든 클래스 분기 → 캐시 미스
```

```js
// ✅ 같은 히든 클래스 공유 (최적화됨)
const a = { x: 1, y: 2 };
const b = { x: 3, y: 4 };

// ❌ 히든 클래스 분기 (최적화 안 됨)
const c = { x: 1 };
c.y = 2; // 나중에 추가 — 히든 클래스가 달라짐
```

### 성능 고려 정리

| 상황                     | 문제              | 해결 방법                  |
| ------------------------ | ----------------- | -------------------------- |
| 런타임 프로토타입 변경   | 히든 클래스 무효화 | `setPrototypeOf` 사용 금지 |
| 깊은 체인 반복 접근      | 매번 탐색 발생    | 로컬 변수에 캐싱           |
| 루프 내 프로퍼티 조회    | 탐색 반복         | 루프 밖에서 캐싱           |
| 동적 프로퍼티 추가       | 히든 클래스 분기  | 생성자에서 모든 속성 선언  |

> **정리:** 프로토타입 체인은 탐색 비용이 있으며, 런타임 프로토타입 교체는 엔진의 히든 클래스 최적화를 무력화한다. 깊은 체인 반복 접근은 로컬 변수로 캐싱하고, 프로퍼티는 생성자에서 미리 선언해 구조 변경을 최소화한다.

## 3. 익명 클래스를 사용하는 구체적인 사례

### 익명 클래스란?

이름 없이 정의되는 클래스로, 클래스 표현식 형태로 사용된다.

```js
// 기명 클래스
class Dog { bark() {} }

// 익명 클래스
const Dog = class { bark() {} };

// 즉시 인스턴스화
const dog = new class { bark() { console.log("왈왈"); } }();
dog.bark(); // "왈왈"
```

### 사례 1 — 팩토리 함수에서 조건부 클래스 반환

```js
function createLogger(type) {
  if (type === "console") {
    return new class {
      log(msg) { console.log(`[LOG] ${msg}`); }
      error(msg) { console.error(`[ERROR] ${msg}`); }
    }();
  }
  if (type === "silent") {
    return new class {
      log() {}   // 아무것도 안 함
      error() {}
    }();
  }
}

const logger = createLogger("console");
logger.log("서버 시작"); // "[LOG] 서버 시작"

const silent = createLogger("silent");
silent.log("무시됨"); // 출력 없음
```

### 사례 2 — 일회성 싱글톤

이름을 부여할 필요 없이 단 하나의 인스턴스만 만들 때 사용한다.

```js
// 전역 설정 객체 — 한 번만 필요
const config = new class {
  #env = "production";

  get env() { return this.#env; }
  isDev() { return this.#env === "development"; }
  isProd() { return this.#env === "production"; }
}();

console.log(config.env);     // "production"
console.log(config.isProd()); // true
```

### 사례 3 — 테스트에서 Mock 객체

```js
// 실제 DB 대신 테스트용 가짜 구현
function createUserService(db) {
  return { getUser: (id) => db.find(id) };
}

// 테스트 코드
const mockDb = new class {
  find(id) { return { id, name: "테스트유저" }; }
  save() { return true; }
}();

const service = createUserService(mockDb);
console.log(service.getUser(1)); // { id: 1, name: "테스트유저" }
```

### 사례 4 — 전략 패턴 (Strategy Pattern)

```js
// 결제 방식별 전략
function processPayment(amount, strategy) {
  return strategy.pay(amount);
}

// 각 전략을 익명 클래스로 정의
const kakaoPayStrategy = new class {
  pay(amount) { return `카카오페이 ${amount}원 결제`; }
}();

const cardStrategy = new class {
  pay(amount) { return `카드 ${amount}원 결제`; }
}();

processPayment(10000, kakaoPayStrategy); // "카카오페이 10000원 결제"
processPayment(5000, cardStrategy);       // "카드 5000원 결제"
```

### 사례 5 — 이벤트 핸들러 캡슐화

```js
button.addEventListener("click", new class {
  #count = 0;

  handleEvent(e) {
    this.#count++;
    console.log(`클릭 ${this.#count}회`);
    if (this.#count >= 3) {
      e.target.disabled = true;
    }
  }
}());
// 클릭 상태를 외부로 노출하지 않고 핸들러 내부에 캡슐화
```

> **정리:** 익명 클래스는 이름이 필요 없는 일회성 구현에서 사용한다. 팩토리 함수의 조건부 반환, 일회성 싱글톤, 테스트 Mock, 전략 패턴이 대표적인 사례다. 재사용할 필요가 없을 때 익명 클래스로 코드를 간결하게 유지한다.

## 4. 인스턴스 속성과 프로토타입 속성의 차이점과 상속

### 인스턴스 속성 vs 프로토타입 속성

```js
class Dog {
  // 인스턴스 속성 — 각 인스턴스가 독립적으로 소유
  constructor(name) {
    this.name = name;   // 인스턴스 속성
  }

  // 프로토타입 속성 — 모든 인스턴스가 공유
  bark() {              // 프로토타입 속성
    console.log(`${this.name}: 왈왈`);
  }
}

const a = new Dog("멍멍이");
const b = new Dog("바둑이");

// 인스턴스 속성: 각자 별도 소유
console.log(a.name); // "멍멍이"
console.log(b.name); // "바둑이"

// 프로토타입 속성: 동일한 함수 공유
console.log(a.bark === b.bark); // true — 같은 함수 참조
```

### 메모리 구조

```
인스턴스 속성:
  a ──▶ { name: "멍멍이" }   ← a만의 공간
  b ──▶ { name: "바둑이" }   ← b만의 공간

프로토타입 속성:
  a ──▶ { name: "멍멍이", __proto__: Dog.prototype }
  b ──▶ { name: "바둑이", __proto__: Dog.prototype }
                                      ↓
                             Dog.prototype.bark  ← 한 번만 저장
```

```js
// 인스턴스 속성에 함수를 넣으면 낭비
class Dog {
  constructor(name) {
    this.name = name;
    this.bark = function() { console.log("왈왈"); }; // ❌ 인스턴스마다 함수 생성
  }
}

const dogs = Array.from({ length: 1000 }, (_, i) => new Dog(`강아지${i}`));
// bark 함수가 1000개 생성됨
```

### 프로퍼티 섀도잉

인스턴스에 같은 이름의 속성을 추가하면 프로토타입 속성을 가린다.

```js
class Animal {
  type = "동물"; // 인스턴스 속성 (클래스 필드)
}
Animal.prototype.sound = "..."; // 프로토타입 속성

const cat = new Animal();
console.log(cat.sound); // "..." (프로토타입에서 조회)

cat.sound = "야옹"; // 인스턴스에 추가 → 프로토타입을 가림 (섀도잉)
console.log(cat.sound); // "야옹" (인스턴스에서 조회)
console.log(Animal.prototype.sound); // "..." (프로토타입은 변경 안 됨)

delete cat.sound; // 인스턴스 속성 제거
console.log(cat.sound); // "..." (프로토타입이 다시 보임)
```

### 상속 시 일어나는 일

```js
class Animal {
  constructor(name) {
    this.name = name; // 인스턴스 속성
  }
  eat() { console.log(`${this.name}가 먹는다`); } // 프로토타입 속성
}

class Dog extends Animal {
  constructor(name) {
    super(name); // Animal의 constructor 호출 → this.name 설정
  }
  bark() { console.log(`${this.name}: 왈왈`); } // 프로토타입 속성
}

const d = new Dog("멍멍이");
```

상속 시 프로토타입 체인 구조:

```
d (인스턴스)
  └── { name: "멍멍이" }           ← 인스턴스 속성
  └── __proto__: Dog.prototype
        └── { bark: f }            ← Dog 프로토타입 속성
        └── __proto__: Animal.prototype
              └── { eat: f }       ← Animal 프로토타입 속성
              └── __proto__: Object.prototype
                    └── { toString: f, ... }
```

```js
d.bark(); // Dog.prototype에서 발견
d.eat();  // Animal.prototype까지 체인 탐색 후 발견
d.toString(); // Object.prototype까지 탐색 후 발견
```

### 상속과 메서드 오버라이딩

```js
class Animal {
  speak() { return "..."; }
}

class Dog extends Animal {
  speak() { return "왈왈"; } // 오버라이딩 — Dog.prototype에 추가
}

class Puppy extends Dog {
  speak() {
    return `${super.speak()}! 왈왈!`; // super로 부모 메서드 호출
  }
}

const p = new Puppy();
p.speak(); // "왈왈! 왈왈!"
```

```
speak() 탐색:
  Puppy.prototype.speak → 발견 (오버라이딩됨)
  super.speak() → Dog.prototype.speak → "왈왈"
```

### 인스턴스 속성 vs 프로토타입 속성 비교

| 구분        | 인스턴스 속성            | 프로토타입 속성           |
| ----------- | ------------------------ | ------------------------- |
| 저장 위치   | 각 인스턴스 내부         | `prototype` 객체          |
| 메모리      | 인스턴스마다 별도 할당   | 모든 인스턴스가 공유      |
| 변경 범위   | 해당 인스턴스만 영향     | 모든 인스턴스에 영향      |
| 주요 용도   | 상태 (name, age 등)      | 동작 (메서드)             |
| 확인 방법   | `hasOwnProperty()` → true | `hasOwnProperty()` → false |

> **정리:** 인스턴스 속성은 각 인스턴스가 독립적으로 소유하는 상태값이고, 프로토타입 속성은 모든 인스턴스가 공유하는 메서드다. 상속 시 프로토타입 체인이 연결되어 부모의 메서드를 탐색할 수 있으며, 자식 클래스에서 같은 이름으로 정의하면 오버라이딩된다.
