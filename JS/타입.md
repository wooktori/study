## 1. 동적 타입 언어 vs 정적 타입 언어

| 구분           | 동적 타입             | 정적 타입                   |
| -------------- | --------------------- | --------------------------- |
| 타입 결정 시점 | 런타임                | 컴파일 타임                 |
| 타입 선언      | 불필요                | 필요                        |
| 예시           | JavaScript, Python    | TypeScript, Java, C++       |
| 장점           | 유연하고 빠른 개발    | 타입 오류 사전 감지, 안정성 |
| 단점           | 런타임 타입 오류 가능 | 코드 장황, 초기 학습 비용   |

```js
// 동적 타입 — 같은 변수에 다른 타입 할당 가능
let x = 10;
x = "hello"; // 에러 없음
```

## 2. 자바스크립트를 정적 타입 언어처럼 사용 가능?

**가능하다.** 대표적인 방법은 **TypeScript** 사용이다.

```ts
// TypeScript — 타입 명시
function add(a: number, b: number): number {
  return a + b;
}

add(1, "2"); // ❌ 컴파일 에러 발생
```

그 외 방법으로는 **JSDoc** 주석으로 타입 힌트를 제공하거나, **Flow** 같은 정적 타입 검사 도구를 사용할 수 있다.

```js
// JSDoc으로 타입 힌트
/**
 * @param {number} a
 * @param {number} b
 * @returns {number}
 */
function add(a, b) {
  return a + b;
}
```

## 3. 자바스크립트는 왜 Number 타입 하나로 정수 실수 모두 처리?

자바스크립트의 `Number`는 **IEEE 754 배정밀도 부동소수점** 방식을 따른다. 64비트로 정수와 실수를 모두 표현하기 때문에 별도의 `int`, `float` 타입을 두지 않는다.

- 장점: 타입 구분 없이 단순하게 숫자를 다룰 수 있음
- 단점: 부동소수점 오차 발생, 안전한 정수 범위 제한 (`2^53 - 1`)

```js
console.log(0.1 + 0.2); // 0.30000000000000004
console.log(Number.MAX_SAFE_INTEGER); // 9007199254740991 (2^53 - 1)
```

## 4. BigInt 성능 문제

**있다.** `BigInt`는 임의 정밀도를 지원하기 때문에 `Number`보다 연산 속도가 느리다.

- 일반 정수 연산 대비 **2~10배 느릴 수 있음**
- `Number`와 혼용 불가 (명시적 변환 필요)
- 암호화, 금융처럼 큰 정수가 필요한 경우에만 사용 권장

```js
const big = 9007199254740991n + 1n; // ✅
const mix = 9007199254740991n + 1; // ❌ TypeError
```

## 5. Number, BigInt 외에 다른 선택지?

| 방법                    | 설명                                               |
| ----------------------- | -------------------------------------------------- |
| **문자열로 처리**       | `"9007199254740993"` — 표시 목적, 연산 불가        |
| **decimal.js / big.js** | 소수점 정밀 연산 라이브러리                        |
| **WASM**                | Rust/C++로 작성한 고정밀 연산을 WebAssembly로 호출 |

실무에서 소수점 정밀도가 중요한 경우 (금융 계산 등) `decimal.js` 사용이 일반적이다.

## 6. 태그드 템플릿 활용

태그드 템플릿은 템플릿 리터럴 앞에 **함수(태그)를 붙여** 문자열을 가공하는 기법이다.

```js
function highlight(strings, ...values) {
  return strings.reduce((result, str, i) => {
    return result + str + (values[i] ? `<b>${values[i]}</b>` : "");
  }, "");
}

const name = "철수";
const age = 20;
console.log(highlight`이름: ${name}, 나이: ${age}`);
// 이름: <b>철수</b>, 나이: <b>20</b>
```

**실전 활용 예시**

- `styled-components` — CSS-in-JS 스타일 정의
- SQL 인젝션 방지 — 입력값 이스케이프 처리
- 다국어(i18n) 처리

## 7. 변수의 선언과 할당 과정

자바스크립트 엔진은 코드 실행 전 **소스 코드를 평가**하는 단계를 거친다.

```
1. 선언 단계 — 변수 이름을 실행 컨텍스트의 스코프에 등록
2. 초기화 단계 — 메모리 공간 확보, undefined로 초기화
3. 할당 단계 — 실제 값을 메모리에 저장
```

```js
console.log(a); // undefined (호이스팅 — 선언만 끌어올려짐)
var a = 10;

console.log(b); // ❌ ReferenceError (TDZ)
let b = 20;
```

| 키워드  | 호이스팅 | 초기화    | TDZ |
| ------- | -------- | --------- | --- |
| `var`   | ✅       | undefined | ❌  |
| `let`   | ✅       | 미초기화  | ✅  |
| `const` | ✅       | 미초기화  | ✅  |

## 8. undefined vs null 차이

|           | `undefined`                 | `null`                            |
| --------- | --------------------------- | --------------------------------- |
| 의미      | 값이 **할당되지 않은** 상태 | 값이 **의도적으로 없음**을 나타냄 |
| 설정 주체 | 자바스크립트 엔진           | 개발자                            |
| typeof    | `"undefined"`               | `"object"` ⚠️ (역사적 버그)       |
| 용도      | 초기화되지 않은 변수        | 빈 값을 명시적으로 표현           |

```js
let a;
console.log(a); // undefined

let b = null;
console.log(b); // null

console.log(typeof null); // "object" — 자바스크립트 초기 버그
```

## 9. NaN과 NaN을 같은 값으로 평가하는 방법

`NaN`은 자기 자신과 같지 않은 유일한 값이다.

```js
console.log(NaN === NaN); // false
```

**같다고 판단하는 방법 3가지**

```js
// 1. Number.isNaN() — 권장
console.log(Number.isNaN(NaN)); // true

// 2. Object.is()
console.log(Object.is(NaN, NaN)); // true

// 3. isNaN() — 주의: 타입 변환이 일어남
console.log(isNaN("hello")); // true (문자열도 true — 부정확)
console.log(Number.isNaN("hello")); // false (정확)
```

## 10. NaN을 다른 값과 비교할 때 주의할 점

`NaN`은 모든 비교 연산에서 `false`를 반환한다.

```js
console.log(NaN == NaN); // false
console.log(NaN === NaN); // false
console.log(NaN > 1); // false
console.log(NaN < 1); // false
console.log(NaN >= NaN); // false
```

따라서 **`NaN` 여부를 확인할 때 반드시 `Number.isNaN()`을 사용**해야 한다.

```js
// ❌ 잘못된 방법
if (value === NaN) {
} // 항상 false

// ✅ 올바른 방법
if (Number.isNaN(value)) {
}
```

## 11. Object.is vs == vs ===

```js
// == 타입 변환 발생
console.log(1 == "1"); // true
console.log(null == undefined); // true

// === 타입 변환 없음
console.log(1 === "1"); // false
console.log(NaN === NaN); // false
console.log(+0 === -0); // true

// Object.is — NaN, +0/-0 정확히 구분
console.log(Object.is(NaN, NaN)); // true
console.log(Object.is(+0, -0)); // false
```

> 일반적으로 `===` 사용을 권장하며, `NaN`이나 `+0/-0` 비교가 필요한 경우 `Object.is`를 사용한다.

## 12. !! 를 사용하는 이유

`!!`는 값을 **Boolean으로 명시적으로 변환**하기 위해 사용한다.

```js
console.log(!!"hello"); // true
console.log(!!0); // false
console.log(!!null); // false
console.log(!!{}); // true
```

`Boolean()` 함수와 동일하지만 더 짧게 쓸 수 있어 실무에서 자주 사용한다.

```js
// 활용 예 — 조건부 렌더링 대신 boolean 값 명시
const isLoggedIn = !!user; // user가 있으면 true, null/undefined면 false
```

## 13. + 연산자와 - / \* 연산자의 차이점

`+`는 **문자열 연결 연산자**로도 동작하기 때문에 타입 변환 방식이 다르다.

```js
// + 연산자 — 문자열이 있으면 문자열 연결
console.log(1 + "2"); // "12"
console.log(1 + 2 + "3"); // "33" (왼쪽부터 계산)

// -, *, / 연산자 — 항상 숫자로 변환 후 연산
console.log("5" - 2); // 3
console.log("5" * "2"); // 10
console.log("10" / 2); // 5
```

## 14. truthy 값과 falsy 값

### falsy 값 (7가지)

```js
(false, 0, -0, 0n, "", null, undefined, NaN);
```

### truthy 값 (falsy를 제외한 모든 값)

```js
// 주의: 비어있어도 truthy인 것들
console.log(!!{}); // true — 빈 객체
console.log(!![]); // true — 빈 배열
console.log(!!"0"); // true — "0" 문자열
console.log(!!" "); // true — 공백 문자열
```

## 15. null과 undefined의 타입 변환

|             | 숫자  | 문자열        | Boolean |
| ----------- | ----- | ------------- | ------- |
| `null`      | `0`   | `"null"`      | `false` |
| `undefined` | `NaN` | `"undefined"` | `false` |

```js
console.log(+null); // 0
console.log(+undefined); // NaN
console.log(`${null}`); // "null"
console.log(`${undefined}`); // "undefined"
console.log(Boolean(null)); // false
console.log(Boolean(undefined)); // false
```

## 16. 소수점 정확한 연산 방법

부동소수점 오차를 피하는 방법들이다.

```js
// 문제
console.log(0.1 + 0.2); // 0.30000000000000004

// 방법 1 — 정수로 변환 후 연산
console.log((0.1 * 10 + 0.2 * 10) / 10); // 0.3

// 방법 2 — toFixed() + parseFloat
console.log(parseFloat((0.1 + 0.2).toFixed(10))); // 0.3

// 방법 3 — Number.EPSILON 허용 오차 비교
function isEqual(a, b) {
  return Math.abs(a - b) < Number.EPSILON;
}
console.log(isEqual(0.1 + 0.2, 0.3)); // true

// 방법 4 — decimal.js 라이브러리 (실무 권장)
// const x = new Decimal(0.1).plus(0.2); // 0.3
```

## 17. Symbol 활용 방법

`Symbol`은 **유일하고 변경 불가능한** 원시값이다.

```js
const id = Symbol("id");
const id2 = Symbol("id");
console.log(id === id2); // false — 항상 고유
```

**주요 활용 패턴**

```js
// 1. 객체의 유일한 키 — 충돌 방지
const KEY = Symbol("key");
const obj = { [KEY]: "secret" };
console.log(obj[KEY]); // "secret"
console.log(Object.keys(obj)); // [] — 열거되지 않음

// 2. Well-known Symbol — 내장 동작 커스터마이징
class MyArray {
  [Symbol.iterator]() {
    let i = 0;
    const data = [1, 2, 3];
    return {
      next() {
        return i < data.length
          ? { value: data[i++], done: false }
          : { done: true };
      },
    };
  }
}

for (const val of new MyArray()) {
  console.log(val); // 1, 2, 3
}

// 3. 상수 enum 대체
const Direction = {
  UP: Symbol("UP"),
  DOWN: Symbol("DOWN"),
};
```

## 18. console.log({}+[]), console.log([] ==![]) 결과

### `{}+[]`

```js
console.log({} + []); // "[object Object]"
```

- `{}` → `"[object Object]"` 로 문자열 변환
- `[]` → `""` 로 문자열 변환
- `+` 연산자 → 문자열 연결 → `"[object Object]"`

> ⚠️ 단, `{}+[]`를 콘솔에 직접 입력하면 `{}` 를 빈 블록으로 해석해 `0`이 나올 수 있다.

### `[] == ![]`

```js
console.log([] == ![]); // true
```

단계별 분석:

1. `![]` → `false` (빈 배열은 truthy이므로 반전하면 false)
2. `[] == false`
3. `false` → `0` (Boolean → Number)
4. `[]` → `""` → `0` (Array → String → Number)
5. `0 == 0` → **true**
