## 1. 함수 선언문 vs 함수 표현식

### 차이 정리

```js
// 함수 선언문 (Function Declaration)
function greet(name) {
  return `안녕, ${name}`;
}

// 함수 표현식 (Function Expression)
const greet = function (name) {
  return `안녕, ${name}`;
};

// 화살표 함수 표현식 (Arrow Function Expression)
const greet = (name) => `안녕, ${name}`;
```

### 핵심 차이: 호이스팅

```js
// 함수 선언문 — 선언 전에 호출 가능
greet("철수"); // "안녕, 철수" ✅
function greet(name) {
  return `안녕, ${name}`;
}

// 함수 표현식 — 선언 전에 호출 불가
greet("철수"); // TypeError: greet is not a function ❌
const greet = function (name) {
  return `안녕, ${name}`;
};
```

### 언제 무엇을 선택할까?

| 상황                   | 선택        | 이유                            |
| ---------------------- | ----------- | ------------------------------- |
| 유틸 함수, 독립적 로직 | 함수 선언문 | 호이스팅으로 코드 순서 자유로움 |
| 콜백, 조건부 할당      | 함수 표현식 | 값으로 다루기 적합              |
| 간단한 변환, 메서드    | 화살표 함수 | `this` 바인딩 없음, 간결함      |
| 생성자 함수            | 함수 선언문 | `new` 키워드 사용 가능          |

```js
// ✅ 함수 선언문 — 독립적인 유틸
function formatDate(date) {
  return date.toISOString().slice(0, 10);
}

// ✅ 함수 표현식 — 콜백으로 전달
const numbers = [1, 2, 3];
const doubled = numbers.map(function (n) {
  return n * 2;
});

// ✅ 화살표 함수 — 간결한 변환
const doubled = numbers.map((n) => n * 2);
```

> **원칙:** 팀 컨벤션을 우선시한다. 개인 코드라면 화살표 함수를 기본으로, `this`가 필요한 경우 함수 표현식, 독립 유틸은 함수 선언문을 사용한다.

## 2. arguments 객체가 유사 배열인 이유

### 유사 배열이란?

배열처럼 인덱스로 접근하고 `length` 속성이 있지만, 배열 메서드(`map`, `filter` 등)를 사용할 수 없는 객체이다.

```js
function foo() {
  console.log(arguments[0]); // 1 — 인덱스 접근 가능
  console.log(arguments.length); // 3 — length 있음
  arguments.map((x) => x * 2); // ❌ TypeError: arguments.map is not a function
}

foo(1, 2, 3);
```

### 왜 진짜 배열이 아닌가?

`arguments`는 `Array.prototype`을 상속하지 않는 **일반 객체**이기 때문이다.

```js
function foo() {
  console.log(Object.prototype.toString.call(arguments)); // [object Arguments]
  console.log(Array.isArray(arguments)); // false
}
```

### 역사적 이유

자바스크립트(1995년 설계) 당시, 가변 인수를 처리하기 위해 `arguments`를 도입했다. 당시에는 배열로 만들면 메모리 비용이 크다고 판단해 단순 객체로 설계했다.

### 배열로 변환하는 방법

```js
function foo() {
  // 방법 1 — Array.from
  const arr = Array.from(arguments);

  // 방법 2 — 스프레드 연산자
  const arr = [...arguments];

  // 방법 3 — slice 사용 (구식)
  const arr = Array.prototype.slice.call(arguments);

  arr.map((x) => x * 2); // ✅ 이제 배열 메서드 사용 가능
}
```

> ES6 이후에는 `arguments` 대신 **나머지 매개변수(`...args`)** 사용을 권장한다. 나머지 매개변수는 진짜 배열이다.

## 3. Function 생성자 함수의 보안·성능 문제

### Function 생성자란?

```js
// 문자열로 함수를 동적 생성
const add = new Function("a", "b", "return a + b");
add(1, 2); // 3
```

### 보안 문제: eval과 동일한 위험

문자열을 코드로 실행하기 때문에 **코드 인젝션 공격**에 취약하다.

```js
// ❌ 사용자 입력이 코드로 실행될 수 있음
const userInput = "alert('해킹!')"; // 악의적인 입력
const fn = new Function(userInput);
fn(); // 실행됨!
```

CSP(Content Security Policy) 설정 시 `new Function`은 차단 대상이다.

### 성능 문제

일반 함수는 파싱 단계에서 컴파일되지만, `Function` 생성자는 **런타임에 문자열을 파싱·컴파일**한다.

```
일반 함수:   파싱(1회) → 실행 (빠름)
Function():  실행 시마다 파싱 → 컴파일 → 실행 (느림)
```

### 스코프 문제

`Function` 생성자로 생성한 함수는 **전역 스코프에서만 실행**된다. 렉시컬 스코프를 따르지 않는다.

```js
const x = "전역";

function outer() {
  const x = "지역";
  const fn = new Function("console.log(x)");
  fn(); // "전역" — 지역 변수 x에 접근 못함
}

outer();
```

### 사용을 피해야 하는 이유 요약

| 문제   | 내용                            |
| ------ | ------------------------------- |
| 보안   | 코드 인젝션 취약점, CSP 차단    |
| 성능   | 런타임 파싱·컴파일로 느림       |
| 스코프 | 렉시컬 스코프 무시, 전역만 접근 |
| 디버깅 | 소스맵 없음, 에러 추적 어려움   |

> **원칙:** `new Function`과 `eval`은 사용하지 않는다. 동적 로직이 필요하다면 전략 패턴(객체로 분기)을 사용한다.

## 4. 자바스크립트가 참조에 의한 전달을 지원하지 않는 이유

### 값에 의한 전달 vs 참조에 의한 전달

```js
// 값에 의한 전달 (Call by Value) — 원시값
let a = 1;
function foo(x) {
  x = 100; // 복사본을 수정
}
foo(a);
console.log(a); // 1 — 원본 불변

// 참조에 의한 전달 (Call by Reference) — C++ 예시
// void foo(int &x) { x = 100; } → 원본이 바뀜
```

### 자바스크립트의 실제 동작: 공유에 의한 전달

자바스크립트는 **참조값(메모리 주소)을 복사해서 전달**한다. 이를 **Call by Sharing** 이라 한다.

```js
// 객체 — 참조값이 복사됨
let obj = { name: "철수" };

function foo(o) {
  o.name = "영희"; // 같은 객체를 수정 → 원본에 영향
}

foo(obj);
console.log(obj.name); // "영희" — 원본 변경됨

// 하지만 재할당은 원본에 영향 없음
function bar(o) {
  o = { name: "민수" }; // 새 객체를 가리키도록 재할당
}

bar(obj);
console.log(obj.name); // "영희" — 원본 불변
```

```
원본:   obj → { name: "철수" }
전달:   o   → { name: "철수" }  ← 같은 객체를 가리킴 (주소 복사)

o.name = "영희"  → 같은 객체 수정 → 원본에도 반영
o = { ... }     → o가 새 객체를 가리킴 → 원본과 분리
```

### 왜 참조 전달을 지원하지 않는가?

| 이유        | 설명                                                |
| ----------- | --------------------------------------------------- |
| 예측 가능성 | 변수 자체가 바뀌면 코드 추적이 어려워짐             |
| 안전성      | 함수가 호출자의 변수를 마음대로 바꾸면 버그 발생    |
| 설계 철학   | 함수는 입력을 받아 출력을 반환하는 독립 단위로 설계 |
| 싱글 스레드 | 공유 상태 변이를 줄여 동시성 문제 회피              |

> 정리: 자바스크립트는 **항상 값을 복사해 전달**한다. 원시값은 값 자체를, 객체는 참조값(주소)을 복사한다.

## 5. 함수를 일급 객체로 다루는 것이 어려운 이유

### 일급 객체(First-class Object)란?

다음 조건을 만족하는 객체를 말한다.

1. 변수에 할당할 수 있다
2. 함수의 인수로 전달할 수 있다
3. 함수의 반환값이 될 수 있다
4. 자료구조(배열, 객체)에 저장할 수 있다

```js
// 자바스크립트에서 함수는 모두 가능
const fn = () => 42; // 1. 변수 할당
[1, 2].map(fn); // 2. 인수 전달
const wrap = () => fn; // 3. 반환값
const obj = { method: fn }; // 4. 객체 저장
```

### 언어 설계 측면의 어려움

**1. 타입 시스템의 복잡성**

```
일반 언어: int, string 등 값 타입만 관리
함수가 일급 객체: 함수의 타입 = "어떤 타입을 받아 어떤 타입을 반환하는가"
→ (int → string), (int → (string → bool)) 같은 고차 타입 필요
→ 타입 추론이 기하급수적으로 복잡해짐
```

**2. 메모리·GC 관리**

```js
function outer() {
  const data = "중요한 데이터";
  return function inner() {
    return data; // 클로저로 data를 캡처
  };
}
// outer가 끝나도 data가 살아있어야 함
// GC가 "이 변수가 함수에 캡처됐는지" 추적해야 함
```

함수가 일급 객체면 클로저가 자연스럽게 생기고, GC는 참조 추적이 훨씬 복잡해진다.

**3. 최적화의 어려움**

```
함수가 값이면 → 어디서든 전달·저장·호출 가능
→ 컴파일러가 "이 함수가 어디서 호출될지" 알 수 없음
→ 인라인 최적화, 호출 그래프 분석이 어려워짐
```

**4. 동시성 문제**

함수를 값으로 공유하면, 여러 스레드가 같은 함수를 동시에 실행할 때 상태(클로저 변수)를 공유하게 된다. 멀티스레드 언어에서는 락(Lock), 동기화가 필요하다.

**5. 스택 vs 힙 결정**

일반 값은 스택에 올리면 되지만, 함수 객체(클로저 포함)는 언제 사라질지 알 수 없어 **힙에 동적 할당**해야 한다. 이는 메모리 오버헤드를 유발한다.

> 이런 복잡성 때문에 초기 C, Java 등은 함수를 일급 객체로 지원하지 않았다. 자바스크립트는 처음부터 함수를 일급 객체로 설계했기에 함수형 프로그래밍이 자연스럽다.

## 6. 고차 함수와 콜백 함수의 차이

### 정의

| 용어          | 정의                                              |
| ------------- | ------------------------------------------------- |
| **콜백 함수** | 다른 함수에 **인수로 전달되는** 함수              |
| **고차 함수** | 함수를 **인수로 받거나 반환값으로 반환하는** 함수 |

### 관계

**콜백 함수**는 역할(다른 함수에 전달되는 것), **고차 함수**는 그것을 받는 쪽의 특성이다. 두 개념은 쌍을 이룬다.

```js
// forEach — 고차 함수
// function(item) — 콜백 함수
[1, 2, 3].forEach(function (item) {
  console.log(item); // 콜백: 인수로 전달된 함수
});
//           ↑ 고차 함수: 함수를 인수로 받음
```

### 고차 함수의 두 가지 형태

```js
// 형태 1 — 함수를 인수로 받음
function repeat(n, fn) {
  // repeat이 고차 함수
  for (let i = 0; i < n; i++) fn(i);
}
repeat(3, console.log); // console.log가 콜백 함수

// 형태 2 — 함수를 반환함
function multiplier(factor) {
  // multiplier가 고차 함수
  return function (number) {
    // 반환된 함수
    return number * factor;
  };
}
const double = multiplier(2); // double은 반환된 함수
double(5); // 10
```

### 실무에서 자주 보는 고차 함수

```js
const numbers = [1, 2, 3, 4, 5];

// map — 변환
const doubled = numbers.map((n) => n * 2); // [2, 4, 6, 8, 10]

// filter — 필터링
const evens = numbers.filter((n) => n % 2 === 0); // [2, 4]

// reduce — 축적
const sum = numbers.reduce((acc, n) => acc + n, 0); // 15

// 체이닝
const result = numbers
  .filter((n) => n % 2 !== 0) // 홀수만
  .map((n) => n * 3); // 3배
// [3, 9, 15]
```

### 차이 요약

| 구분 | 콜백 함수                | 고차 함수                       |
| ---- | ------------------------ | ------------------------------- |
| 역할 | 인수로 **전달되는** 함수 | 함수를 **받거나 반환하는** 함수 |
| 관점 | 전달되는 쪽              | 받는/반환하는 쪽                |
| 관계 | 고차 함수에게 전달됨     | 콜백 함수를 인수로 받음         |
| 예시 | `n => n * 2`             | `Array.map`, `setTimeout`       |

## 7. 부분 적용 활용 예시

### 부분 적용(Partial Application)이란?

함수의 인수 일부를 미리 고정해 **새로운 함수를 만드는 기법**이다.

```js
// 일반 함수
function add(a, b) {
  return a + b;
}

// 부분 적용 — a를 10으로 고정
function add10(b) {
  return add(10, b);
}

add10(5); // 15
add10(20); // 30
```

### bind를 이용한 부분 적용

```js
function multiply(a, b) {
  return a * b;
}

const double = multiply.bind(null, 2); // a=2 고정
const triple = multiply.bind(null, 3); // a=3 고정

double(5); // 10
triple(5); // 15
```

### 실무 활용 예시

**1. API URL 빌더**

```js
const buildUrl = (baseUrl, endpoint) => `${baseUrl}${endpoint}`;

const apiUrl = buildUrl.bind(null, "https://api.example.com");

apiUrl("/users"); // "https://api.example.com/users"
apiUrl("/products"); // "https://api.example.com/products"
```

**2. 로그 레벨 고정**

```js
const log = (level, message) => console.log(`[${level}] ${message}`);

const info = log.bind(null, "INFO");
const warn = log.bind(null, "WARN");
const error = log.bind(null, "ERROR");

info("서버 시작"); // [INFO] 서버 시작
warn("메모리 부족"); // [WARN] 메모리 부족
error("DB 연결 실패"); // [ERROR] DB 연결 실패
```

**3. 이벤트 핸들러에 데이터 주입**

```js
function handleClick(userId, event) {
  console.log(`유저 ${userId} 클릭`, event.target);
}

// 각 버튼에 userId를 미리 고정
document
  .getElementById("btn1")
  .addEventListener("click", handleClick.bind(null, 1));
document
  .getElementById("btn2")
  .addEventListener("click", handleClick.bind(null, 2));
```

**4. 세율 계산기**

```js
const applyTax = (rate, price) => price * (1 + rate);

const applyVAT = applyTax.bind(null, 0.1); // 부가세 10%
const applyLuxury = applyTax.bind(null, 0.3); // 사치세 30%

applyVAT(1000); // 1100
applyLuxury(1000); // 1300
```

**5. 커링으로 부분 적용 구현**

```js
const curry = (fn) => (a) => (b) => fn(a, b);

const curriedAdd = curry((a, b) => a + b);
const add5 = curriedAdd(5); // a=5 고정

add5(3); // 8
add5(10); // 15
```

> 부분 적용은 코드 재사용성을 높이고, 반복되는 인수를 제거해 코드를 간결하게 만든다.

## 8. 나머지 매개변수 vs arguments 객체

### 기본 비교

```js
// arguments 객체 (ES5 이전 방식)
function oldSum() {
  let total = 0;
  for (let i = 0; i < arguments.length; i++) {
    total += arguments[i];
  }
  return total;
}

// 나머지 매개변수 (ES6 이후 방식)
function newSum(...numbers) {
  return numbers.reduce((acc, n) => acc + n, 0);
}
```

### 핵심 차이

| 구분             | `arguments`           | 나머지 매개변수 (`...args`) |
| ---------------- | --------------------- | --------------------------- |
| 타입             | 유사 배열 객체        | 진짜 배열 (`Array`)         |
| 배열 메서드      | ❌ 직접 사용 불가     | ✅ 바로 사용 가능           |
| 화살표 함수      | ❌ 없음               | ✅ 사용 가능                |
| 일부 인수만 수집 | ❌ 모든 인수          | ✅ 원하는 인수만            |
| 명시성           | ❌ 파라미터에 안 보임 | ✅ 파라미터에 명시됨        |

### 화살표 함수에서의 차이

```js
// 화살표 함수에는 arguments가 없음
const arrow = () => {
  console.log(arguments); // ❌ ReferenceError (또는 외부 스코프의 arguments)
};

// 나머지 매개변수는 화살표 함수에서도 동작
const arrow = (...args) => {
  console.log(args); // ✅ [1, 2, 3]
};
arrow(1, 2, 3);
```

### 일부 인수만 수집

```js
// 나머지 매개변수 — 첫 번째 이후의 인수만 수집
function log(level, ...messages) {
  messages.forEach((msg) => console.log(`[${level}] ${msg}`));
}

log("INFO", "서버 시작", "포트: 3000");
// [INFO] 서버 시작
// [INFO] 포트: 3000

// arguments로는 이런 분리가 불가
function log() {
  const level = arguments[0];
  const messages = Array.from(arguments).slice(1); // 변환 후 slice 필요
}
```

### 배열 메서드 사용

```js
function sum(...numbers) {
  return numbers
    .filter((n) => n > 0) // ✅ 바로 filter 사용
    .reduce((acc, n) => acc + n, 0);
}

function oldSum() {
  return Array.from(arguments) // 변환 필요
    .filter((n) => n > 0)
    .reduce((acc, n) => acc + n, 0);
}
```

> **원칙:** `arguments`는 레거시 코드에서만 마주친다. 새 코드에서는 항상 나머지 매개변수를 사용한다.

## 9. 이벤트 루프와 콜백 큐의 상호작용

### 자바스크립트 런타임 구조

```
┌─────────────────────────────────┐
│          Call Stack             │  ← JS 코드 실행
│  (함수 호출 시 프레임 쌓임)      │
└─────────────────────────────────┘
         ↑ 비어있으면 꺼냄
┌─────────────────────────────────┐
│          Event Loop             │  ← 감시자
└─────────────────────────────────┘
         ↑ 우선순위에 따라
┌──────────────┐  ┌──────────────────┐
│  Microtask   │  │   Macrotask      │
│  Queue       │  │   Queue          │
│  (Promise,   │  │   (setTimeout,   │
│   queueMicro │  │    setInterval,  │
│   task)      │  │    I/O, UI)      │
└──────────────┘  └──────────────────┘
```

### 이벤트 루프의 동작 순서

```
1. Call Stack이 비어있는지 확인
2. Microtask Queue가 비어있을 때까지 모두 실행
3. Macrotask Queue에서 하나만 꺼내 실행
4. 다시 1로 돌아감
```

### 예시로 이해하기

```js
console.log("1");

setTimeout(() => console.log("2"), 0); // Macrotask Queue

Promise.resolve().then(() => console.log("3")); // Microtask Queue

console.log("4");

// 출력 순서: 1 → 4 → 3 → 2
```

```
실행 흐름:
1. "1" 출력 (Call Stack)
2. setTimeout 등록 → Macrotask Queue에 추가
3. Promise.then 등록 → Microtask Queue에 추가
4. "4" 출력 (Call Stack)
5. Call Stack 비워짐 → Event Loop 확인
6. Microtask Queue 확인 → "3" 출력
7. Microtask Queue 비워짐 → Macrotask Queue 확인
8. setTimeout 콜백 꺼냄 → "2" 출력
```

### Microtask가 Macrotask보다 먼저 실행되는 이유

Microtask(Promise)는 **현재 작업이 끝난 직후** 실행된다. 다음 렌더링이나 I/O 이전에 처리해야 하는 중요한 작업(상태 일관성 보장 등)을 위해 높은 우선순위를 갖는다.

```js
// Microtask가 쌓이면 Macrotask가 지연됨
Promise.resolve()
  .then(() => Promise.resolve()) // 중첩 Microtask
  .then(() => Promise.resolve())
  .then(() => console.log("Microtask 완료"));

setTimeout(() => console.log("Macrotask"), 0);

// Microtask 완료 → Macrotask 순으로 출력
```

## 10. setTimeout 비동기 코드의 실행 순서는 어떻게 결정?

### 기본 원리

`setTimeout`은 지정된 시간이 지난 후 **Macrotask Queue에 콜백을 추가**한다. Call Stack이 비어야 실행된다.

```js
console.log("시작");

setTimeout(() => console.log("setTimeout"), 0); // 0ms지만 즉시 실행 아님

console.log("끝");

// 시작 → 끝 → setTimeout
```

`setTimeout(fn, 0)`은 "지금 당장"이 아니라 "현재 콜 스택이 비면 실행"이다.

### 타이머 값이 부정확할 수 있는 이유

```js
const start = Date.now();
setTimeout(() => {
  console.log(Date.now() - start); // 0ms를 지정했어도 실제로는 4ms 이상
}, 0);
```

- 브라우저의 최소 타이머 간격: **4ms** (HTML 스펙)
- Call Stack이 바쁘면 대기 시간 증가

### 여러 setTimeout의 실행 순서

```js
setTimeout(() => console.log("A"), 100);
setTimeout(() => console.log("B"), 0);
setTimeout(() => console.log("C"), 50);

// B → C → A (지연 시간 순)
```

같은 지연 시간이면 등록 순서대로 실행된다.

```js
setTimeout(() => console.log("1번"), 0);
setTimeout(() => console.log("2번"), 0);
setTimeout(() => console.log("3번"), 0);

// 1번 → 2번 → 3번 (등록 순서)
```

### Promise와 setTimeout의 순서

```js
setTimeout(() => console.log("setTimeout"), 0); // Macrotask
Promise.resolve().then(() => console.log("Promise")); // Microtask

// Promise → setTimeout
// Microtask가 항상 Macrotask보다 먼저 실행
```

### 실무 예시: 렌더링 이후 실행

```js
// DOM 업데이트 후 실행하고 싶을 때
element.style.display = "block";

setTimeout(() => {
  // 브라우저가 렌더링할 시간을 준 뒤 실행
  element.getBoundingClientRect(); // 정확한 크기 측정 가능
}, 0);
```

### 실행 순서 결정 규칙 요약

| 순위 | 큐              | 예시                             |
| ---- | --------------- | -------------------------------- |
| 1    | Call Stack      | 동기 코드                        |
| 2    | Microtask Queue | `Promise.then`, `queueMicrotask` |
| 3    | Macrotask Queue | `setTimeout`, `setInterval`, I/O |

> `setTimeout(fn, 0)`은 "비동기적으로, 가능한 빨리 실행"이지 "즉시 실행"이 아니다.
