## 1. useImmer 훅이란? 목적은?

**Immer 라이브러리를 기반으로 만든 훅으로, 불변성을 직접 관리하지 않고도 상태를 직접 변경하는 것처럼 업데이트할 수 있게 해준다.**

```bash
npm install use-immer
```

```jsx
import { useImmer } from "use-immer";

function Form() {
  const [form, updateForm] = useImmer({
    name: "홍길동",
    address: { city: "서울", district: "강남구" }
  });

  function handleCityChange(city) {
    updateForm(draft => {
      draft.address.city = city; // 직접 변경처럼 작성 — Immer가 불변 객체로 변환
    });
  }
}
```

기존 방식과 비교하면 중첩 객체 업데이트가 훨씬 간결해진다.

```jsx
// ❌ 기존 방식 — 중첩이 깊을수록 스프레드가 복잡
setForm(prev => ({
  ...prev,
  address: { ...prev.address, city: "부산" }
}));

// ✅ useImmer — 직관적
updateForm(draft => { draft.address.city = "부산"; });
```

## 2. 사용자 정의 훅이란? 어떻게 생성하는지? 장점은?

**훅 로직을 재사용 가능하게 추출한 함수**다. 이름이 반드시 `use`로 시작해야 하며, 내부에서 다른 훅을 사용할 수 있다.

```jsx
// useFetch.js — 데이터 패칭 로직을 커스텀 훅으로 추출
function useFetch(url) {
  const [data, setData] = useState(null);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    let cancelled = false;

    fetch(url)
      .then(res => res.json())
      .then(json => {
        if (!cancelled) {
          setData(json);
          setIsLoading(false);
        }
      })
      .catch(err => {
        if (!cancelled) {
          setError(err);
          setIsLoading(false);
        }
      });

    return () => { cancelled = true; };
  }, [url]);

  return { data, isLoading, error };
}

// 사용 — 어느 컴포넌트에서나 재사용
function UserList() {
  const { data, isLoading, error } = useFetch("/api/users");
  if (isLoading) return <div>로딩 중...</div>;
  if (error) return <div>오류 발생</div>;
  return <ul>{data.map(u => <li key={u.id}>{u.name}</li>)}</ul>;
}
```

### 장점

- **재사용성** — 같은 로직을 여러 컴포넌트에서 공유
- **관심사 분리** — UI 로직과 비즈니스 로직을 분리
- **가독성** — 컴포넌트 코드가 간결해짐
- **테스트 용이성** — 훅을 독립적으로 테스트 가능

## 3. 렌더 props와 고차 컴포넌트를 사용해야 하는가?

**훅이 도입된 이후로는 두 패턴 모두 대부분 커스텀 훅으로 대체된다.** 그러나 완전히 사라지지 않았고 특정 상황에서는 여전히 유용하다.

| 패턴 | 현재 권장 | 아직 유효한 경우 |
|---|---|---|
| 고차 컴포넌트 (HOC) | 커스텀 훅으로 대체 | `React.memo`, `react-redux`의 `connect`, 레거시 클래스 컴포넌트 |
| 렌더 props | 커스텀 훅으로 대체 | UI 렌더링 방식을 외부에서 제어해야 할 때 |

```jsx
// 렌더 props 패턴
function DataProvider({ render }) {
  const data = useFetchData();
  return render(data); // 렌더링 방식을 외부에 위임
}

// 같은 로직을 커스텀 훅으로 — 더 단순
function Component() {
  const data = useFetchData(); // 직접 호출
  return <div>{data}</div>;
}
```

## 4. effect를 사용자 정의 훅으로 옮기는 것을 추천하는지?

**추천한다.** 특히 다음 경우에 강하게 권장된다.

### 1. 같은 이펙트가 여러 컴포넌트에서 반복될 때

```jsx
// ❌ 반복되는 코드
function ComponentA() {
  const [width, setWidth] = useState(window.innerWidth);
  useEffect(() => {
    const handler = () => setWidth(window.innerWidth);
    window.addEventListener("resize", handler);
    return () => window.removeEventListener("resize", handler);
  }, []);
}

// 같은 코드가 ComponentB, ComponentC에도 반복...

// ✅ 커스텀 훅으로 추출
function useWindowWidth() {
  const [width, setWidth] = useState(window.innerWidth);
  useEffect(() => {
    const handler = () => setWidth(window.innerWidth);
    window.addEventListener("resize", handler);
    return () => window.removeEventListener("resize", handler);
  }, []);
  return width;
}
```

### 3. 이펙트를 독립적으로 테스트하고 싶을 때

단, 무조건 추출하는 것은 오히려 과도한 추상화를 만든다. 한 곳에서만 쓰이고 로직이 단순하다면 컴포넌트 안에 그대로 두는 것이 낫다.

> **정리:** `useImmer`는 복잡한 중첩 상태를 불변성 걱정 없이 업데이트한다. 커스텀 훅은 재사용 가능한 상태 로직을 추출하는 핵심 수단이며, 훅 도입 이후 HOC와 렌더 props의 주요 사용 사례를 대부분 대체했다. 이펙트가 반복되거나 복잡해지면 커스텀 훅으로 분리하는 것을 권장한다.
