# WebSocket을 이용한 실시간 채팅 구현

## 1. 요구사항 정의

모임 생성 후 모임 참여자 간의 즉각적인 소통 기능의 필요성을 도출하여 실시간 채팅을 구현하기로 결정했다.

---

## 2. 기술 선택: SSE vs WebSocket

### SSE (Server-Sent Events)

| 항목        | 내용                                     |
| ----------- | ---------------------------------------- |
| 통신 방향   | 서버 → 클라이언트 (단방향)               |
| 연결 방식   | HTTP 기반 지속 연결                      |
| 메세지 전송 | 클라이언트 → 서버 시 별도 HTTP 요청 필요 |
| 적합한 사례 | 알림, 피드 업데이트 등 서버 푸시 전용    |

### WebSocket

| 항목        | 내용                                    |
| ----------- | --------------------------------------- |
| 통신 방향   | 서버 ↔ 클라이언트 (양방향)              |
| 연결 방식   | 초기 HTTP Upgrade 후 TCP 기반 지속 연결 |
| 메세지 전송 | 단일 연결로 송수신 동시 처리            |
| 적합한 사례 | 채팅, 실시간 협업 등 양방향 상호작용    |

### WebSocket 선택 이유

SSE는 서버 → 클라이언트 단방향 통신으로, 메세지 전송 시 추가적인 HTTP 요청이 필요해 실시간 상호작용에 한계가 있다고 판단했다. 채팅은 메세지 **송신과 수신이 동시에** 이루어져야 하므로 단일 연결로 양방향 통신이 가능한 WebSocket을 선택했다.

> **서버 부담에 대한 검토**
> WebSocket은 연결을 유지하는 특성상 서버 리소스 부담이 존재한다. 하지만 아래 두 가지 이유로 수용 가능하다고 판단했다.
>
> - 모임 특성상 채팅방 최대 동시 접속 인원이 **12명으로 제한**
> - 모임 시작 시점으로부터 **하루가 지난 채팅방은 자동 삭제** 처리

## 3. 기술 스택

프로토콜 레이어를 나누어 구현했다.

```
SockJS        : WebSocket 미지원 환경 폴백 처리
STOMP         : 메세지 라우팅 및 구독/발행 패턴 (pub/sub)
```

- **`sockjs-client`** : WebSocket을 지원하지 않는 환경에서도 동작할 수 있도록 폴백 제공
- **`@stomp/stompjs`** : STOMP 프로토콜을 통해 destination 기반 메세지 라우팅 처리

## 4. 서버 엔드포인트 구조

```
연결 엔드포인트
  /ws-chat

구독 (Subscribe)
  /sub/chat/room/{roomId}   채팅방 메세지 수신
  /sub/user/{userId}        개인 알림 수신 (강퇴 등)

발행 (Publish)
  /pub/chat/message         메세지 전송
```

## 5. 구현 구조

WebSocket 연결 목적에 따라 두 개의 훅으로 분리했다.

### useChatSocket — 채팅방 내부

채팅방 진입 시 연결되며 메세지 송수신과 개인 알림을 처리한다.

```ts
const { isConnected, messages, sendMessage } = useChatSocket({
  roomId,
  userId,
  accessToken,
  enabled: !!chatInfo, // 채팅방 정보 로드 후 연결
  onMessage: (message) => {
    // 메세지 수신 콜백
    if (message.messageType === "KICK" && message.targetUserId === userId) {
      router.replace("/"); // 강퇴 시 메인으로 이동
      return;
    }
    setChatMessages((prev) => [...prev, message]);
  },
});
```

**연결 설정**

```ts
const client = new Client({
  webSocketFactory: () => new SockJS(`${API_BASE_URL}/ws-chat`),
  connectHeaders: { Authorization: `Bearer ${accessToken}` },
  reconnectDelay: 6000, // 재연결 대기 6초
  heartbeatIncoming: 4000, // 서버 heartbeat 수신 주기
  heartbeatOutgoing: 4000, // 클라이언트 heartbeat 발신 주기
});
```

**구독 처리**

```ts
client.onConnect = () => {
  // 채팅방 메세지 구독
  client.subscribe(`/sub/chat/room/${roomId}`, (message) => {
    const payload: ChatMessage = JSON.parse(message.body);
    onMessageRef.current?.(payload);
  });

  // 개인 알림 구독 (강퇴 등)
  client.subscribe(`/sub/user/${userId}`, (message) => {
    const payload = JSON.parse(message.body);
    onNotificationRef.current?.(payload);
  });
};
```

**메세지 전송**

```ts
const sendMessage = (content: string) => {
  client.publish({
    destination: "/pub/chat/message",
    body: JSON.stringify({
      chatRoomId: roomId,
      content: content.trim(),
    }),
  });
};
```

**콜백 안정성 처리 (onMessageRef 패턴)**

`onMessage` 콜백은 매 렌더링마다 새 함수 참조가 생성된다. 이를 WebSocket effect의 dependency에 포함시키면 불필요한 재연결이 발생한다. ref로 최신 콜백을 추적하여 WebSocket 연결을 유지하면서도 항상 최신 콜백이 실행되도록 처리했다.

```ts
const onMessageRef = useRef(onMessage);

useEffect(() => {
  onMessageRef.current = onMessage; // 연결 유지, 콜백만 갱신
}, [onMessage]);
```

**언마운트 시 정리**

```ts
return () => {
  if (clientRef.current?.active) {
    clientRef.current.deactivate();
  }
  clientRef.current = null;
  setIsConnected(false);
  setMessages([]);
};
```

### useChatListSocket — 채팅 목록

채팅 목록 화면에서 모든 채팅방을 구독하여 새 메세지 수신 시 목록을 실시간 갱신한다.

```ts
useChatListSocket({
  userId,
  accessToken,
  chatRoomIds, // 사용자가 속한 모든 채팅방 ID 배열
});
```

```ts
// 모든 채팅방 구독
chatRoomIds.forEach((roomId) => {
  client.subscribe(`/sub/chat/room/${roomId}`, () => {
    // 새 메세지 수신 시 채팅 목록 React Query 캐시 무효화
    queryClient.invalidateQueries({ queryKey: ["chatList", userId] });
  });
});
```

## 6. 메세지 흐름

### 채팅방 진입 시

```
page.tsx (Server Component)
  accessToken, userId 추출

ChatRoomPage (Client Component)
  useGetChatMessages()    이전 메세지 REST API로 초기 로드
  useChatSocket()         WebSocket 연결 및 실시간 메세지 수신
  useReadMessages()       입장 시 읽음 처리
```

### 메세지 전송 흐름

```
사용자 입력 (ChatInput)
  → handleSubmit()
  → sendMessage(text)         [useChatSocket]
  → STOMP publish /pub/chat/message
  → 서버에서 /sub/chat/room/{roomId} 로 브로드캐스트
  → 구독 중인 모든 클라이언트의 onMessage 콜백 실행
  → setChatMessages((prev) => [...prev, message])
  → 화면 렌더링
```

### 강퇴 처리 흐름

```
방장이 강퇴 요청 (UserOutModal)
  → useKickUser() mutation
  → 서버에서 /sub/user/{targetUserId} 로 KICK 메세지 전송
  → 대상 클라이언트 onMessage에서 messageType === 'KICK' 감지
  → router.replace('/')  메인 화면으로 강제 이동
  → Toast 알림 표시
```

## 7. 메세지 타입

```ts
interface ChatMessage {
  messageId: number;
  senderId: number | null;
  senderName: string | null;
  senderProfileImage: string | null;
  content: string;
  messageType: "TEXT" | "SYSTEM" | "KICK";
  timestamp?: string;
  createdAt?: string;
  targetUserId: number;
}
```

| 타입     | 설명                          |
| -------- | ----------------------------- |
| `TEXT`   | 일반 채팅 메세지              |
| `SYSTEM` | 입장/퇴장 등 시스템 알림      |
| `KICK`   | 강퇴 처리 (targetUserId 대상) |
